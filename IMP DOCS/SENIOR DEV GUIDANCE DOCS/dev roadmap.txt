One major architectural rule
There will be three separate layers:
1. Game data
Things like:
Constituency
Persona
Party
Manifesto
Business
Balance parameters
2. Simulation
Things like:
ElectionEngine
EconomySystem
CampaignSystem
TurnSystem
AISystem
3. Presentation
Things like:
Map
Buttons
Panels
Animations
HUD
Menus
The election mathematics should not know that a button exists.
The map should not calculate election results.
The UI should request information from the simulation rather than secretly becoming part of the simulation.
That separation will save us enormous amounts of pain later.

Another important decision
I'm going to be deliberately strict about the GDD.
If you later say:
"Let's add newspapers."
I'll ask whether it belongs in v0.1.
If the answer is no, it goes into the backlog.
If we discover that a GDD mechanic is mathematically weak, however, we will change the GDD. The GDD is a design document, not a religious text.
Our objective isn't to preserve every sentence you've written.
Our objective is to make a genuinely good game.
