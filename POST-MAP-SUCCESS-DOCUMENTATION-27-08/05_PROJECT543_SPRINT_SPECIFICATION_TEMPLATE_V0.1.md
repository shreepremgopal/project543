## Why This Sprint Now?

Explain the dependency or risk that makes this sprint appropriate.

## Design Before Code

Define entities, inputs, outputs, invariants, specified formulas, unresolved decisions, configuration and error handling before implementation.

## Acceptance Criteria

Every criterion must be testable.

## Tests

Define tests before declaring completion.

## Out of Scope

Explicitly state what will not be built.

## Stop Conditions

Stop and review architecture when GDD requirements conflict, an unspecified rule is required, an interface must change, UI coupling appears, data assumptions change or a core formula would have to be invented.

## Documentation Deliverables

Code, tests, design specification, architecture decisions and updated logs.

## Sprint Review

Record what was built, tested, failed, assumptions discovered, decisions changed, what is locked, what remains unresolved and whether the roadmap needs adjustment.
