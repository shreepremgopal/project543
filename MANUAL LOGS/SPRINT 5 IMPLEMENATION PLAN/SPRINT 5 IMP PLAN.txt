# 1. Executive Decision

Sprint 5 should **not** be treated as "add ideology."

That would undersell the importance of this sprint.

Sprint 5 should establish the first version of the game's **Political Decision Engine**.

The player should eventually be able to look at a constituency and think:

> "We are ideologically strong here, but our base is weak. This constituency contains a large persuadable bloc. I don't have enough information to know whether we're actually competitive. Should I spend money polling it, or should I invest elsewhere?"

That is the experience we are building toward.

The system therefore has five layers:

```text
                 POLITICAL WORLD
                       │
             ┌─────────▼─────────┐
             │  IDEOLOGICAL      │
             │  STRUCTURE        │
             └─────────┬─────────┘
                       │
             ┌─────────▼─────────┐
             │ PERSONA           │
             │ PREFERENCES       │
             └─────────┬─────────┘
                       │
             ┌─────────▼─────────┐
             │ CONSTITUENCY      │
             │ COMPOSITION       │
             └─────────┬─────────┘
                       │
             ┌─────────▼─────────┐
             │ POLITICAL         │
             │ SUPPORT           │
             └─────────┬─────────┘
                       │
             ┌─────────▼─────────┐
             │ PLAYER            │
             │ INFORMATION       │
             └───────────────────┘
```

The **election system comes later**.

The **economy/campaign system comes later**.

The **AI comes later**.

But all of those systems will eventually depend on this one.

That is why Sprint 5 must be built exceptionally cleanly.

# 2. The Central Design Philosophy

The game should follow one fundamental principle:

> **The simulation may be mathematically sophisticated, but the player should only need to understand strategic relationships.**

The player does **not** need to see:

`exp(-λD²)`

The player needs to understand:

> "These voters are highly compatible with our political position."

Likewise, the player does not need to see:

`responsive_pool × constituency_affinity`

They need to understand:

> "We have a weak existing base here, but there is a large persuadable population."

This produces:

### Low cognitive barrier

while retaining:

### Extremely high strategic ceiling.

That is exactly the "easy to start, extremely hard to master" target.

## O1 — Establish the political coordinate system

A canonical six-dimensional political space.

## O2 — Establish mathematical persona preferences

## O3 — Establish party/persona alignment

Consider two personas with identical ideology.

Persona A:

```text

National     0.10
```

They occupy the same political location.

But they don't necessarily react equally to ideological disagreement.

That is where depth begins.

# 10. Alignment Mathematics

The first Sprint 5 implementation should use a weighted distance.

Let:

```text
P = party position
Q = persona position
w = persona salience
```

Calculate:

```text
D = 0.5 × sqrt(
    Σ wi × (Pi - Qi)²
)
```

This normalizes the result approximately to:

```text
0 ≤ D ≤ 1
```

Then:

```text
Alignment = exp(-λD²)
```

Initial balance parameter:

```text
λ = 2.0
```

**Important:** this is a V0.1 balance configuration, not eternal doctrine.

It must live in configuration.

---

# 11. Why This Formula Is Strong

It gives us:

### Exact ideological match

```text
D = 0
Alignment = 1
```

### Moderate difference

Alignment declines gradually.

### Severe difference

Alignment declines strongly.

But it does not create:

> "You are 0.01 away, therefore you suddenly lose 20%."

That matters.

Political systems should not feel like arbitrary cliffs.

# 12. A Crucial Architectural Decision

The alignment engine must be replaceable.

Why?

Because multidimensional political preferences can eventually become **non-separable**.

In other words:

> The importance of one political dimension may depend upon another dimension.

A future Project543 model might eventually need:

```text
distance =
diagonal salience
+
cross-dimensional interactions
```

rather than only independent dimensions.

That is why Sprint 5 should define:

```text
AlignmentModel
```

as an abstraction/interface rather than permanently coupling every system to one formula.

Research in political analysis supports the underlying concern: multidimensional preferences can include interaction/non-separability, including models using weighted quadratic forms rather than only simple diagonal weights. ([Cambridge University Press][1])

**Do not implement that advanced model now.**

Build the architecture that can accommodate it later.

# 13. Constituency Composition

This is one of the most important decisions in the sprint.

A constituency is not:

```text
one average voter
```

It is:

```text
Persona distribution
```

For example:

```text

Persona B  24%
Persona C  18%
Persona D  14%
Persona E   8%
Persona F   4%
```

The percentages must total 100%.

# 14. The Dangerous Shortcut We Must Avoid

Do **not** calculate:

```text
constituency ideology
=
average(persona ideology)
```

and then throw away the personas.

That would destroy strategic depth.

Why?

Because:

```text
50% extreme-left
50% extreme-right
```

and:

```text
100% moderate
```

can have similar mathematical averages while being radically different political coalitions.

The distributions must remain authoritative.

# 15. Constituency Affinity

For party `q`:

```text
CA(c,q)
=
Σ persona_share × persona_alignment
```

So a constituency's ideological affinity is the weighted aggregate of its actual persona population.

This creates **coalition geometry**.

The player isn't merely asking:

> "Is this constituency left or right?"

They are eventually asking:

> "Which coalition can we assemble here?"

That is much more interesting.

# 16. Base Support

Base support is deliberately separate.

A constituency might contain:

```text
high ideological compatibility
```

but:

```text
low existing party loyalty
```

Another constituency might have:

```text
mediocre ideological compatibility
```

but:

```text
massive historical base
```

Both should be strategically valuable for different reasons.

---

# 17. Base Support Formula

For party `q`:

```text
B(c,q) ∈ [0,1]
```

Total base support:

```text
Σ B(c,q) ≤ 1
```

Responsive population:

```text
R(c) = 1 - Σ B(c,q)
```

If:

```text
Σ B(c,q) > 1
```

the data is invalid.

**Hard failure.**

No automatic normalization.

---

# 18. Political Potential

The first support foundation:

```text
Potential(c,q)
=
B(c,q)
+
R(c) × CA(c,q)
```

This gives us two fundamentally different political sources:

```text
BASE
+
RESPONSIVE
```

This distinction will become incredibly useful later.

---

# 19. Current Support

Normalize:

```text
Support(c,q)
=
Potential(c,q)
/
Σ Potential(c,k)
```

Therefore:

```text
Σ Support(c,q) = 1
```

This gives us a coherent current political state.

But:

# Support is NOT votes.

That boundary must be preserved.

# 26. Why Polling Must Not Reveal Exact Numbers

If:

```text
Deep Poll = exact truth
```

then the game becomes:

> Whoever can afford information gets certainty.

That is not good strategy.

Instead:

```text
Deep Poll
=
better estimate
+
smaller uncertainty
```

not:

```text
Deep Poll = omniscience
```

Real polling is itself uncertain: sampling error is only one source of uncertainty, with nonresponse, weighting/design effects, noncoverage and measurement also contributing. ([Pew Research Center][2])
